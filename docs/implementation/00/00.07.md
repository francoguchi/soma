# Foundation shell and runtime convergence

## Outcome

The already-functional Foundation host/UI converges on SOMA's accepted operational visual grammar, exact workspace navigation, clean text presentation, and correctly separated host-vs-controller runtime state without discarding useful implementation.

## Work

### Backend

Separate process-internal lifecycle from launcher/controller observation and update health, launcher and tray projections accordingly. Preserve the existing trust model.

### Frontend

Converge the authenticated shell and Diagnostics surface on the accepted dense terminal-inspired operational grammar. Detached source Run must retain no host console window, and Stop must recover only a proven-dead exact-owned stale runtime registration while preserving fail-closed behavior for live/untrusted/unreachable candidates. Keep pane focus localized, give the active pane title a readable current tint, and keep pane headers fixed while their bodies scroll. Durable-job label/value content is vertically centered inside each cell while the odd final cell remains deliberately asymmetric in natural grid order. Theme every governed scrollbar through shared tokens with accessible native fallback.

Before later feature UI begins, finish the accepted Foundation style library/cascade behind stable `soma.css`. Add a richer but semantic terminal-accent palette (current violet, info/cyan, muted success green, warning amber, destructive coral), the shared `$` / `--` / `>` console-cue hierarchy, and a muted-green READY status. Shared components consume reusable primitives/tokens; feature CSS must not reproduce or override them. Preserve working auth/runtime/diagnostics behavior and the established viewport/status/navigation convergence.

Use the canonical SOMA brand palette and existing semantic-token/accessibility rules. Preserve working auth, diagnostics data, capability truth, routing and responsive state instead of rewriting the application.
